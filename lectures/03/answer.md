- 第1回（素のLLM）とエージェントの回答の違い  
  「宿題の3レベルとは何か」と質問し、回答を比較した。
  - 素のLLM（`app.ask`）は、「初級・中級・上級」など、一般的な講座で想定される区分を例示した。
  - エージェント（`app.agent`）は、講座で定められた「基礎・実装・発展」の3レベルを挙げ、いずれか1つに取り組めばその回の宿題は完了すると答えた。回答の末尾には「関係する回：第1回」と表示された。

- `--trace` で確認したツール名と引数
  - 用語比較では、`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` が各1回呼ばれた。
  - 第2回の確認問題を依頼すると、`make_quiz({'lecture': 2})` が1回呼ばれた。ツールは問題と答えを返し、最終回答にはLoRAの仕組みや特徴を問う問題が表示された。

- 1つの質問に対するLLMとツールの呼び出し回数
  - 用語比較：`requests=2`、`tool_calls=2`
  - 確認問題の出題：`requests=2`、`tool_calls=1`

- 追加したツールとdocstringの説明  
  `make_quiz(lecture: int)` を追加した。docstringには「指定した回の用語から確認問題を1問作る」と記載し、「第2回の確認問題を出して」という利用例を添えた。`--list-tools` で登録を確認し、`uv run pytest -q` では11件すべてのテストが合格した。

## 宿題

- 取り組んだレベル：基礎

- やったこと
  - `app/tools.py` の `search_glossary` の説明文を「用語を1つだけ入れる」から「比較する用語をまとめて1回の query に入れる」に変更した。
  - 変更前後で同じ質問「LoRA とQLoRAの違いは？」を実行し、`--trace` の出力を比較した。

- 結果
  - 変更前は `LoRA` と `QLoRA` を別々に検索した（`tool_calls=2`）。
  - 変更後は `LoRA QLoRA` を1つの検索語として渡した（`tool_calls=1`）。
  - モデルへの問い合わせ回数は、どちらも `requests=2` だった。
  - どちらの回答も、LoRAはベースモデルの重みを固定して小さな行列を学習し、QLoRAはベースモデルの重みを量子化したうえでLoRAを使うと説明した。

- 気づき・疑問
  - 検索処理は同じでも、説明文を1文変えると、今回の実行ではモデルが渡す検索語とツールの呼び出し回数が変わった。
  - `tool_calls` と `requests` を見比べることで、用語集を検索した回数とモデルに問い合わせた回数を区別できた。

- 取り組んだレベル：実装

- やったこと
  - 学習内容を `learning_log/entries.jsonl` に1件ずつ追記するツール `save_learning_log` を追加した。
  - 保存前にCLIで保存先と内容を表示し、利用者が `y` で承認、`n` で拒否できるようにした。

- 結果
  - 承認時：`y` を入力すると、`--trace` に保存成功を示すツールの戻り値が表示された。保存先のファイルを開き、「第3回でツールの承認処理を学んだ」という内容がJSON形式で1件記録されていることを確認した。
  - 拒否時：`n` を入力すると、`--trace` に `The tool call was denied.` と表示された。拒否前後でファイルは1行のまま、内容も同じだったため、追記されなかったことを確認した。
  - テスト：`uv run pytest -q` を実行し、15件すべてのテストが合格した（4.08秒）。

- 気づき
  - 保存を拒否したときも、モデルは「記録として承りました」と回答した。この文面は保存したようにも読めるが、実際にはファイルへの追記はなかった。ファイルを書き換えるツールの動作を検証する際は、モデルの回答に加え、ツールの実行結果とファイルの変化を確認することが重要だと分かった。
